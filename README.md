# Robo-Advisor — reference architecture and core engine

A design and a working core for a real-time budget/investment advisor:
per-second portfolio valuation over NASDAQ/S&P 500/BIST, daily TEFAS & BES fund
data, and macro-triggered (FED, CPI) rebalancing driven by a regression factor
model and a linear program solved with the simplex method.

## Code

```
backend/app/
  domain/models.py           shared types (Tick, Portfolio, MacroEvent, ...)
  market/
    providers.py             Finnhub WS adapter + REST polling fallback (one socket per venue)
    gateway.py               upstream → Redis last-value cache + pub/sub + batched history
    cache.py                 hot-path last-value cache
    session.py               NASDAQ/BIST trading-session state
    valuation.py             server-side portfolio valuation with FX and staleness
  api/ws.py                  1 Hz snapshot+delta push to the frontend
  macro/
    fed.py                   FRED DFEDTARU step detection, idempotent, surprise-aware
    triggers.py              scenario mapping + cooldown/threshold governance
  analytics/regression.py    HAC-OLS factor model + Type-II ANOVA + p-value shrinkage
  optimization/simplex.py    Konno–Yamazaki MAD linear program (HiGHS dual simplex)
  rebalance/engine.py        trigger → μ → LP → drift gate → orders
  tefas/client.py            TEFAS (YAT) and BES (EMK) end-of-day ingestion
  security/tokens.py         scrypt passwords, JWT access tokens, rotating refresh tokens
  db/                        SQLAlchemy models, session factory, repositories, migrations
  api/auth.py                login / refresh / logout, and the websocket's authenticator
  analytics/panel.py         builds the estimation panel; attributes shocks to pricing days
  rebalance/mandate.py       the customer's mandate, validated before it reaches the LP
  worker/                    scheduled jobs, Redis job locks, APScheduler wiring
migrations/                  Alembic chain (upgrade/downgrade/drift are tested)
  examples/fed_cut_rebalance.py   runnable end-to-end demo
R/macro_factor_model.R       the same regression/ANOVA/LP in R, as a validation twin

mobile/                      React Native + TypeScript iOS client
  src/api/socket.ts          websocket state machine (backoff, watchdog, fatal codes)
  src/state/                 pure snapshot/delta fold + zustand store
  src/screens/               live portfolio, allocation proposal, macro feed
  ios/RoboAdvisor/           Swift: Keychain session storage and Face ID
  server/mock-server.js      dev backend speaking the same wire contract
```

## Run

```bash
cd backend
pip install -r requirements.txt

python -m examples.fed_cut_rebalance   # end-to-end: FED cut → ANOVA → simplex → 500 TL orders
pytest -q                              # 110 tests: LP, triggers, valuation, auth, panel, jobs

DEV_MODE=1 python -m scripts.seed_demo # demo user, mandate, 2y of synthetic history
DEV_MODE=1 uvicorn app.main:app --reload
DEV_MODE=1 python -m app.worker.main   # the scheduler: FED poll, TEFAS ingest, rebalancing
```

```bash
cd mobile
npm install
npm test                               # 43 tests: session, socket, frame folding, formatting
npm run mock                           # fake backend, no API keys
./scripts/bootstrap-ios.sh && npm run ios   # macOS + Xcode
```

The demo and the tests run offline on synthetic data — no API keys needed.
Swap `build_panel()` for `TefasClient.history(...)` and the FRED poller for real
credentials to run it against live data.

## Status

Backend, worker and iOS client are runnable end to end — a FED cut detected on a
schedule produces a persisted decision, which the app renders and the user
confirms with Face ID — with 153 tests across the two (110 Python, 43
TypeScript).

Not yet built: push notifications for rebalance alerts, an intraday history
endpoint, and broker/fund order execution — `confirm` records the decision, it
does not route an order. Market data is still synthetic in the seed; wire
`FRED_API_KEY` and a TEFAS/market-data subscription for real numbers. The Xcode
project is generated by `mobile/scripts/bootstrap-ios.sh` rather than checked in.
