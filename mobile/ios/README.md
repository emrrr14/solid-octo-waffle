# iOS native layer

## What is here, and what is not

| Present | Generated by `scripts/bootstrap-ios.sh` |
|---|---|
| `RoboAdvisor/SecureVault.swift` — Keychain + Face ID module | `RoboAdvisor.xcodeproj` / `.xcworkspace` |
| `RoboAdvisor/SecureVault.m` — the Objective-C bridge declaration | `AppDelegate`, `Info.plist`, `Podfile`, `Pods/` |

The Xcode project is **not** checked in on purpose. A pbxproj written by hand
drifts from whatever React Native version you install and fails in ways that
take an afternoon to unpick; the official template is one command away and is
always consistent with the pinned version.

## Why native code at all

React Native covers the entire product surface here — the whole UI, the
websocket, the state, the formatting — and each native module you add is a
build-config cost forever. Two things genuinely cannot be done in JavaScript:

1. **Keychain.** A bearer token that can move money must not sit in
   `AsyncStorage`, which is a plaintext SQLite file in the app container.
   `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` keeps the token out of
   iCloud backups and off restored devices, and it is reachable only through
   Security.framework.
2. **Face ID.** `LocalAuthentication` has no JS equivalent. The order
   confirmation is gated on it, with a passcode fallback so a failed Face ID in
   bright sun doesn't lock someone out of their portfolio.

Both live in one Swift file, exposed through one `RCT_EXTERN_MODULE` bridge, and
are consumed from TypeScript via `src/native/SecureVault.ts` — which falls back
to in-memory storage with a loud warning when the module is absent, so a
misconfigured build is obvious rather than silently insecure.

## Info.plist keys the bootstrap adds

```xml
<key>NSFaceIDUsageDescription</key>
<string>Portföy işlemlerinizi onaylamak için Face ID kullanılır</string>

<!-- Cleartext for the local mock backend only; production is https/wss -->
<key>NSAppTransportSecurity</key>
<dict><key>NSAllowsLocalNetworking</key><true/></dict>
```

Missing `NSFaceIDUsageDescription` does not produce a permission dialog — iOS
terminates the app the first time `LocalAuthentication` is called. It is a crash,
not a denial.

## Things iOS will do to this app

* **Backgrounding kills the socket.** iOS suspends the process within seconds;
  the socket dies without an `onclose`. `usePortfolioStream` closes deliberately
  on `background`/`inactive` and reconnects on `active` — which also stops the
  app streaming 1 Hz data in someone's pocket.
* **Network changes leave half-open sockets.** Wifi → cellular hands you a
  connection that will never deliver another byte and never fires an event. The
  client's inbound-frame watchdog (45 s, fed by the server's 15 s heartbeat) is
  the only reliable detector.
* **Live prices do not arrive by push.** APNs is not a data channel: for a
  rebalance alert while the app is closed, send a normal push from the backend
  and let the app fetch on open. Background fetch is best-effort and will not run
  every minute, whatever the interval you request.
* **App Review.** A finance app needs a working demo account in App Store
  Connect (reviewers cannot sign up for a brokerage), a privacy policy URL, and
  accurate "Data Used to Track You" answers. The disclaimer on the allocation
  screen exists partly for this reason.
